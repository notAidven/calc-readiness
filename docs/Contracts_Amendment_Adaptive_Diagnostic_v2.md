## 1. Summary & scope

### 1.1 Why change a ratified design

The ratified MST (v1) served the 6-node D1 MVP well, but it does not scale to the Phase-1 full graph (62 in-product nodes across D1–D10 as of 2026-07-25; 48 across D1–D9 when this amendment was written, pre the 2026-07-24 coverage expansion — the argument only gets stronger). Three concrete weaknesses:

1. **Not modeled on the dependency structure.** v1 is a flat 2-stage tree: one pooled routing stage over every node, a single `routing_bar` routing *everyone at once* (`route()` in `engines/diagnostic/src/routing.ts`). But the graph is **not** parallel domain chains — it is a DAG with **`NUM.4` (D1 arithmetic) as the taproot**: the entry node of every domain D2–D9 (`EXP.1`, `RAD.1`, `LIN.1`, `POL.1`, `CG.1`, `FUN.1`, `TRG.1`) lists `NUM.4` as a prerequisite, and `NUM.4` needs `NUM.S/NUM.F/NUM.2/NUM.3`. The instrument should *walk that structure*, not average over it.
2. **Length.** A flat "≈1 item per node" instrument runs ~57–64 items on the full graph, with no pruning — too long for a diagnostic.
3. **Noise.** Routing hinges on the aggregate proportion of **single items per node**; one lucky/unlucky item swings a whole branch. And v1 *already* performs downward inference (`computePlacement` credits a dependent's prereqs) with no confirmation gate — the over-credit / skip risk.

### 1.2 What v2 does

- **One fused instrument, unchanged.** The pretest remains the only onboarding instrument and still doubles as placement (INV-DIAG-3). Reaffirmed.
- **Prerequisite-gated adaptive walk (DAG walk).** The student is probed at an estimated level on the prereq DAG. **Failing a node localizes the floor and prunes everything above it** (never administered); **robustly passing a node ascends and conservatively credits its downward closure** (test-out). A node is eligible only once its prerequisites are resolved-passed.
- **Adaptive, confirmed per-node adjudication.** Each probed node is decided by an adaptive 2-of-3 rule with **asymmetric confirmation**: a single miss never prunes a subtree (a confirmed failure is required before pruning). Bias is deliberately toward *placing-low*, never toward leaving a gap uncovered.
- **Depth-weighted readiness coverage.** The reported score is **coverage of the in-product prereq graph, weighted by prerequisite depth**, computed over the *resolved knowledge state* — not a latent `θ`. Moving from a latent-ability model to a knowledge-state model makes coverage (not `θ`) the native, meaningful cross-domain metric.

### 1.3 What does **not** change

The immutable record tables (Contracts §2), the write-mapping (Contracts §3 — the diagnostic writes `placement_estimate` + assessment records, **never** `mastery`), the DI ports (`engines/diagnostic`), server-side authoritative recomputation, and per-node **pass/fail adjudication from answered items only** (Assessment_Scoring_Spec §6). The additive record fields introduced by v1 (`routing_path`, `scoring_model_version`) are retained and reused. Teammates' consumption points — the record shapes, the mastery service, state reads — are untouched; the shared change is the **metric definition** and the **placement-inference semantics**, which is why this remains an all-hands amendment.

### 2.1 Contracts §2 — `assessment_administration.purpose`

- **v1 wording:** *"Pre and post use the same adaptive blueprint and scoring-model version, administered as a multistage adaptive test; comparability comes from a shared difficulty-aware scoring model and counterbalanced parallel item pools…"*
- **v2 wording:** *"`pre` / `post` / `placement`. Pre and post use the **same prereq-graph version, resolution rules, and `scoring_model_version`**, administered as a **prerequisite-gated adaptive walk**; comparability comes from a **shared graph + resolution + coverage-weight model and counterbalanced parallel item pools**, not from identical forms or an identical routing path. The full walk trace is recorded (see §2.2) so the coverage score is deterministically recomputable."*

### 2.2 Contracts §2 — recorded fields on `assessment_administration` (reuse, no new columns)

- `routing_path` (jsonb) — **repurposed** from "ordered list of stage ids" to the **ordered walk trace**: each probed node id, its per-item outcomes, its adjudicated result (`passed` / `failed` / `borderline`), and the derived tags (`measured` / `inferred` / `pruned`). Sufficient to deterministically reconstruct the resolved knowledge state and recompute coverage (INV-DIAG-4). Still additive; still no existing field changes.
- `scoring_model_version` (int) — now versions the **coverage-weight function + resolution rules** (in addition to the adjudication thresholds). Pre and post MUST share it to be comparable.

### 2.3 Assessment_Scoring_Spec §3 / §5 / §6

- §3 (fixed/parallel or "MST" form language) is superseded by the DAG walk in §4 below. Counterbalanced parallel **item pools** are retained (a student still never sees an identical item pre vs post).
- §5 (reported metric) is replaced: the frontier `θ` is retired as the reported metric in favor of **depth-weighted readiness coverage** (§5 below). `θ` may survive only as an internal, per-node convenience during transition; it is not reported and not the gain.
- §6 ("answered-items-only" denominator) is **retained for per-node adjudication** (each node's pass/fail uses only `correct`/`incorrect` items; faults/`invalid_input` excluded) but **no longer governs the aggregate metric** (see the revised INV-DIAG-2).

## 3. Invariants

### 3.1 Preserved (must remain true by construction)

- **INV-DIAG-1 (mastery firewall).** The diagnostic writes ONLY `placement_estimate`; never `mastery`, `completion_status`, or evidence. Unchanged (the engine has no mastery-writer dependency).
- **INV-DIAG-3 (one instrument).** Exactly one onboarding instrument; placement is derived from the same run as the score. No second testing wall.
- **INV-DIAG-4 (reproducibility).** Given the immutable records + `routing_path` (walk trace) + `scoring_model_version`, the server deterministically recomputes the resolved state and the coverage metric.
- **INV-DIAG-5 (pre/post comparability).** Pre and post use the same graph version, resolution rules, and `scoring_model_version`, with counterbalanced pools. Coverage is a **pure function of the resolved knowledge state**, so it is **path-invariant**: two administrations of the same true state yield the same coverage regardless of the (possibly different) adaptive paths taken. The reported gain is `coverage_post − coverage_pre`.

### 3.2 Revised

- **INV-DIAG-2 (resolved-state metric — REVISED; the principal contract departure).** *v1 required the metric be computed from answered items only, with inference seeding the city but never the score.* v2 computes coverage over the **resolved knowledge state** = measured passes **∪** conservatively-inferred passes (downward-closed). Per-item **adjudication** still uses answered items only (§2.3), but the **aggregate** legitimately includes inference. Safeguards that make this sound: (a) inference fires only on a **robust, confirmed** pass (INV-DIAG-8); (b) **measured and inferred contributions are tagged and separately recoverable**, so a measured-only coverage is always computable for audit; (c) pre and post apply identical resolution rules, so the *gain* reflects real change, not inference drift. *This supersedes an approval-blocker of the ratified amendment and is the item most in need of all-hands scrutiny; the fallback if rejected is a measured-only numerator (§7 item (c)).*

Pruned nodes are always placed **not-ready** (never passed). ## 4. The adaptive design (normative once ratified)

### 4.1 State & the frontier

Each in-scope node holds a walk state ∈ `{ unknown, probing, passed, failed, pruned }`, plus a placement tag ∈ `{ measured, inferred, none }`. The **resolved** state is downward-closed — a node counts as `passed` only with its prerequisites passed (enforced at resolution, INV-DIAG-6) — but **probe ordering is *not* eligibility-gated**: the walk may probe any `unknown` node and relies on **test-out** (a robust pass credits the prereq closure) and **pruning** (a confirmed fail prunes the dependent cone) to stay short. The **frontier** is the depth band separating the student's confirmed passes from their confirmed fails; the walk binary-searches for it.

### 4.2 The walk (information-gain frontier bisection)

Probe *ordering* is a tunable policy; the §3 invariants hold regardless of order (they live in resolution, not selection). The shipped policy is an adaptive frontier bisection:

1. **Entry (gentle low start).** The opening probe eases in near the foundations (`ENTRY_DEPTH`, a shallow tier) so the check never starts hard and a weak student exits after a few items. (The recorded `entry_tier` is provenance only; ordering no longer branches on it.)
2. **Probe** the `unknown` node nearest the **frontier target depth** — a binary search over prerequisite depth. The target is the midpoint of the deepest **measured pass** and the shallowest **measured fail**, so it **jumps up after passes** (toward the leaves, where a robust pass tests out a long prereq chain) and **down after fails** (toward the roots, where a confirmed fail prunes a large cone). Ties prefer the node that resolves the most still-`unknown` nodes either way (`below + above`), then the shallower node, then id (determinism).
3. **On `passed`:** mark `passed (measured)`; if the pass **licenses inference** (INV-DIAG-8), credit the transitive prereq closure as `passed (inferred)`; the target **moves up** (test-out lets the search skip the credited closure). *(Read "licenses inference" rather than "is robust" as of the 2026-07-26 fold — the same rename §5.1 already carries. The rule lives in INV-DIAG-8; this step only says when the walk applies it.)*
4. **On `failed` (confirmed):** mark `failed`; **prune** all transitive dependents to `pruned` (not-ready, never administered); the target **moves down** to localize the **floor** (the deepest layer still passed).
5. **Stop** when no `unknown` node remains. Every reachable node is `passed`/`inferred` or `failed`/`pruned`.

Because both extremes collapse the unknown set fast — a strong student by test-out (probe high, infer the chain), a weak student by pruning (probe low, cut the cone) — the **strongest student is never the longest** and the **weakest exits fastest**; mid-ability students (the widest frontier) probe most. The policy is **graph-agnostic** (an injected `WalkGraph`) and scales sub-linearly with node count: validated on the 48-node product (≤ ~35 probes across ability profiles) and on synthetic deep/wide DAGs up to ~88 nodes. *(That "48-node" figure is a **historical measurement**, not a product-target claim: it records the graph the probe-count validation actually ran against, before the 2026-07-24 coverage expansion took the target to 62. It is left as measured rather than restated.)*

> **✅ RE-MEASURED ON THE 62-NODE GRAPH (2026-07-26).** This paragraph previously closed by saying the probe-count bound had **not** been re-measured at 62 and should be before anyone quoted it. **It has been, twice, and both measurements are recorded.** `docs/Diagnostic_Probe_Cost_Measurement.md` measured the *pre-amendment* policy at a **median of 82 items / 35 nodes** (p90 111/43, p99 132/49, max 145/52; n = 6,000, mild noise) — so "≤ ~35 probes" was a **node** count that cost ~112 items, and quoting it as an instrument-length bound silently swapped the unit. `docs/Contracts_Amendment_Diagnostic_Probe_Policy.md` §1 then measured the **shipped** policy on the same harness and cohort at a **median of 38 items / 30 nodes**, p90 62/40, p99 70/45, capped at the 70-item ceiling, truth accuracy 95.6%. **Quote 38 items at n = 6,000 for the current product, and always state the unit.** The sub-linear scaling claim is unaffected.

### 4.3 Per-node adjudication (confirmation proportional to consequence)

*Amended and folded in 2026-07-26 from `docs/Contracts_Amendment_Diagnostic_Probe_Policy.md`, replacing the flat "adaptive 2-of-3, asymmetric confirm" rule ratified 2026-07-22, and amended again 2026-08-04 from `docs/Contracts_Amendment_Diagnostic_Live_Consequence.md` (the first bullet's static-property clause, pass direction only). This section is normative; each amendment doc is the rationale and the measurement behind its own change.*

**The rule is confirmation proportional to consequence.** Every node opens with **one** item, and the decision stands on that item **unless it would cascade**, in which case the node falls through to the adaptive 2-of-3 unchanged.

- **"Would cascade" is judged per direction, and the two directions are judged independently.** For a **failure** it is a **static** property of `(node, scope, graph)`: the size of the node's in-scope transitive dependent cone (what pruning would remove), never read against the walk's evolving unknown set (INV-DIAG-7). For a **pass** it is the size of the node's in-scope transitive prerequisite closure (what test-out would credit), read either statically or **live** — live meaning only the members of that closure still `unknown` in the resolution the walk has reached, which is what the pass can still *newly* credit. The live reading applies only under a policy that asks for it (`livePassClosure`) and only from the switch point at which the walk has **already** served `liveConsequenceFrom` scorable items (counted over the whole walk, excluding the item being adjudicated); below that point, and under any policy that does not ask, the pass side is the whole static closure exactly as before. A live count is by construction ≤ the static one, so nothing becomes *more* consequential by being read live, and **the threshold itself stays static** (`floor(|scope| × confirmScopeFraction)`, unchanged). **Reproducibility (INV-DIAG-4) is discharged by `adjudicateRecordedWalk`**, which re-decides a recorded walk by folding along `routing_path` and adjudicating each node against the resolution that recorded order had already reached: probe **selection** is never reconstructed, and the reading a record was scored under travels with it in the version-keyed rules registry. **The ratified setting is `livePassClosure: true`, `liveConsequenceFrom: 20`, registered at `scoring_model_version` 3; `liveFailCone` is off.** *(⚠ **Amended 2026-08-04**, superseding the clause folded in 2026-07-26, which read: ""Would cascade" is a static property of `(node, scope, graph)` — never of the walk's evolving unknown set, because `rebuildWalkState` re-buckets response rows by node and re-adjudicates each in isolation rather than replaying the walk, and a dynamic rule could not be reproduced that way (INV-DIAG-4)." That sentence carried its own justification and the justification was falsified: `adjudicateRecordedWalk` reproduces a live rule from the immutable record without replaying the walk, so staticness turns out to have been a sufficient condition for INV-DIAG-4 rather than a necessary one. The two sentences defining each direction's reach are unchanged. Read `DEFAULT_WALK_POLICY` for what is live rather than this line: PR #572 is the change that turns the setting on and was open when this was folded. Superseded text verbatim, the evidence, the version record and — importantly — what the amendment does **not** license: `docs/Contracts_Amendment_Diagnostic_Live_Consequence.md`.)*
- **The threshold is a share of the scope (`7/62`), not an absolute count**, because the damage a wrong call does is relative to the size of the instrument: a cascade of five nodes is most of the 6-node D1 walk and a rounding error in the 62-node walk. It **rounds down**, so on a small scope it reaches 0 and *everything* is confirmed — which is what keeps the live D1 walk bit-identical. The value may be re-tuned by measurement without re-ratification, **only** on the conditions in probe-policy §3.4.1.
- **Consequential node — the ratified 2-of-3, unchanged.** Serve 1 item. **Correct → serve a confirming 2nd**; 2/2 correct → **`passed` (robust)**. **Wrong → serve a 2nd**; 2/2 wrong → serve a **3rd confirming item before any pruning** (INV-DIAG-7); 2-of-3 wrong → **`failed` (confirmed)**.
- **Inconsequential node — decided on the single item.** There is no subtree to remove and little to credit, so the node stops paying for a confirmation it cannot cascade. A single-item pass **licenses inference** (INV-DIAG-8) and seeds placement **2**, not 3.
- **A mixed 2-of-3 correct is a genuine pass.** It resolves `passed` (non-robust), seeds `placement_estimate` **2**, and therefore **clears the `>= 2` test-out unlock bar exactly as a robust pass does** — it tests out of its own lesson. What it does **not** do is credit the prerequisite closure: a borderline pass is non-inferring at any size, and the walk descends to verify. *(Settled 2026-07-26; probe-policy §3.5. Nothing in production branches on 3 versus 2 — every consumer asks `>= 2` — so the distinction is a city-seed grade, and pass/fail is the only boundary with behaviour behind it.)*
- **`robust` and `infers` are two different flags, deliberately.** `robust` means exactly a clean 2/2 and drives the top city seed of **3**. Inference licensing is the separate `infers` flag, so that widening one did not silently shift the 0–3 placement scale §4.4 ratifies. Consequence: **a measured pass no longer implies seed 3.**
- **A node is still decided within at most three scorable items** (`MAX_PROBE_ITEMS = 3`). The amendment reduces the *average* draw, never the maximum, so the §8 pool-depth requirement of ≥3 per served cell is unchanged.
- **Instrument ceiling: 70 scorable items.** A backstop, not a target — the median sits at 38 and ~1.5% of students are genuinely truncated. Nodes it leaves unresolved resolve **fail-closed, unchanged** (INV-DIAG-6): they are `unknown` and seed **0**. *(70 rather than the 60 originally proposed, on the truncated-cohort evidence in probe-policy §6.)*
- Faults (`scoring_error`/`unsupported_expression`/`invalid_input`) are non-scorable and are re-served, never counted (Assessment_Scoring_Spec §6).

**Versioning.** `scoring_model_version` stayed **2** through this amendment. That is not "no record exists yet" — it is provable additivity over a frozen record population, and the recompute path now resolves a record's resolution rules from a version-keyed registry of frozen literals keyed by the record's own version. The proof, its two recorded bounds, and the conditions any future re-tune must meet are in probe-policy §3.4 and §3.4.1.

*(⚠ **The 2026-08-04 live-consequence amendment took it to 3**, and that sentence is left as written because it is a true record of the 2026-07-26 fold, not a claim about today. The live reading could **not** take the additivity route — a node the instrument ceiling leaves with a single outcome and no decision re-adjudicates differently, and `recordScoredOutcome` handles the ceiling landing mid-node, so the population is not frozen and Route B's bar is not met. It went by **Route A** instead: `COVERAGE_SCORING_MODEL_VERSION` 2 → 3, the new rules registered as a frozen literal under version 3 with **version 2's literals left in place**, and the INV-DIAG-5 comparability impact recorded — every existing pre/post pair becomes `not_comparable`, all of them administered at version 2. This is a **different record** from the `blueprint_version` 5 → 6 bump, which belongs to the POL.5 scope widening under D-END4: turning a knob does not move the node set. `docs/Contracts_Amendment_Diagnostic_Live_Consequence.md` §6.)*

### 4.4 Per-node placement (city seed + lesson entry)

The walk is difficulty-agnostic (one routing tier per node until the L1/L3 pools land), so placement is derived from the **evidence already collected**, no extra items: `passed (measured, robust)` (cleared 2/2) → **3**; `passed (measured, non-robust)` or `passed (inferred)` (test-out) → **2**; `failed` with ≥1 correct attempt (partial ground) → **1**; `failed` with no correct attempt, or `pruned` → **0** (not-ready). Placement additionally routes each node's **lesson entry point** (high placement → "prove it" practice; the practice is always the safeguard — a wrong inference just means the student does the practice and, on a miss, is routed into teaching). *(⚠ **AMENDED 2026-07-23, RATIFIED 2026-07-26, FOLDED INTO `docs/Contracts.md` §1.1** — which is the normative source and wins on conflict. This "student still does the practice" safeguard now **gates** only **failed/unresolved** nodes: a **passed** placement (`>= 2`, measured or inferred) unlocks + completes the building **without** the lesson, at **`mastery` 0**. The practice is therefore optional for the *building* but is still the only route to `mastery` and its stars — test-out skips the lesson only, and the storm's `mastery >= 2` gate is unaffected. ## 5. The reported metric: depth-weighted readiness coverage

### 5.1 Definition

Let the in-scope node set **S** = the **in-product nodes** (`product_scope ∈ {mvp, target}`, i.e. `getProductNodes()`) — **62 as of 2026-07-25**; take the denominator from `getProductNodes()`, never from a hard-coded number. Only `retired`/`cut` ids are placeable-only and **excluded from the readiness denominator**. *(Read "the 48 in-product nodes … `extended` (9) and `retired`/`cut` ids are excluded", with a caveat about `TRG.6`'s `secondary` lifecycle status, until the 2026-07-24 coverage expansion (PR #50) promoted all 9 `extended` nodes and TRG.6 into target and the 2026-07-25 RAD.4 append (PR #63) landed; those two populations are now empty.)* Let `depth(n)` = the longest prerequisite path from a root (graph-derived; ranges ~0 for `NUM.S` to ~7 for `RAT.4`). Weight `w(n) = 1 + depth(n)` (rewards climbing the ladder; zero hand-calibration). Let **P** = the resolved-passed set (downward-closed, measured ∪ **inference-licensed**-inferred). *(⚠ Term corrected 2026-07-26, was "robust-inferred". Since `docs/Contracts_Amendment_Diagnostic_Probe_Policy.md` §3.2, inference licensing is a separate flag (`infers`) from `robust`: `robust` still means exactly a clean 2/2 and still drives the top city seed, while a single-item pass whose prerequisite closure is too small to be worth confirming also licenses inference. A borderline 2-of-3 pass licenses it under **neither** term. The membership of **P** is unchanged by the rename on any scope whose confirm threshold rounds to 0, which is every scope served to date; the old term simply stopped naming the right predicate.)*

```
coverage = Σ_{n ∈ P ∩ S} w(n)  /  Σ_{n ∈ S} w(n)          ∈ [0, 1]
gain     = coverage_post − coverage_pre
```

### 5.2 Companion signals (recorded, not the gate number)

- **`coverage_measured`** — the same formula with the numerator restricted to `passed (measured)` (the audit / fallback number for INV-DIAG-2).
- **Per-domain coverage vector** — `coverage` restricted to each domain D1–D9 (the diagnostic profile for the report + city, e.g. "D1 92%, D9 10%").

### 5.3 Properties

Bounded, monotonic, interpretable ("ready for 63% of the prereq graph, +22 pts"), and a **pure, deterministic function** of the resolved state + graph + `scoring_model_version` → reproducible for the Day-12 gate and the core-loop test. Path-invariant (INV-DIAG-5). The D1 MVP "aggregate score difference" gate is the same formula restricted to the 6 D1 nodes (blueprint-matched).

## 6. Calibration & honest disclosure

`depth`/tier weights are **graph-derived and author-assigned**, not IRT-calibrated (calibration needs response volume the build does not produce — Assessment_Scoring_Spec §10 defers this). Coverage is therefore a **provisional** readiness estimate. The honest-disclosure clause (§7a: "uncontrolled, within-instrument pre/post gain") stands, extended with "on a provisional, graph-derived weight scale, pending post-hoc calibration." `scoring_model_version` lets historical coverage be recomputed once real item parameters exist.

## 8. Item-pool depth (authoring consequence)

The 2-of-3 adjudication + counterbalanced pre/post requires each **(node, difficulty) cell** to hold enough authored items that (a) a confirm never repeats a probe item, and (b) the post path does not reuse a pre item. Practical target: **≥3 parallel items per served node per form (A/B)**. The engine degrades gracefully on a thin bank (adjudicates on what exists, records reduced confidence).

**Resolved 2026-07-23 (step 8 done).** The gate was: each v1 assessment form is **one instance per template** (`D1_FORM_A`/`D1_FORM_B` = 1 item per (node, difficulty) cell → 2 items per node), enough for a clean **2/2 robust pass** but **not** the asymmetric-confirm *third* item; the deep `D1_PRACTICE_*` pools are **practice** items the diagnostic never serves. Fixed **additively** by a dedicated **walk assessment pool** — `D1_WALK_ITEM_PACK` (`@cr/item-bank`): `D1_WALK_ITEMS_PER_CELL = 3` parallel **L2** items per node per form (the walk is difficulty-agnostic — its `WalkItemSource` carries no difficulty and placement is a fixed status→seed map — so it probes every node at the one routing difficulty L2 every D1 node authors). Frozen via `freezeDeepParallelForms` to be globally content-distinct (A≠B, and distinct from the v1 pack + practice pool, so the "no item shared across pools" invariant holds); the v1 forms and their pinned hashes are **untouched** until the flip. `createItemPackWalkSource` serves it node-addressed to the engine; `validateWalkPool` guards the ≥3-per-cell depth + A/B disjointness. **Proof the gate is closed:** `services/diagnostic-runtime/src/walk-real-bank.test.ts` drives the shipped walk engine over the real pool + the real authoritative scorer through a **confirmed failure** (2-of-3 wrong) and a **non-robust pass** (2-of-3 correct), each serving three distinct real items — precisely what the v1 bank could not do. (Full-graph item-bank depth beyond D1 remains part of the Days 13–20 expansion.)
