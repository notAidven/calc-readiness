# Achievements: five frames at 1024x580

The rendered evidence for the achievements framework: the moment one is earned, the list
with a mix of earned and unearned on it, the list a brand-new city sees, and the dev hatch a
reviewer reaches all of it by.

**Every frame is 1024x580 and mounted under reduced motion, and the viewport is half the
evidence.** That is the window the team lead reviews on, measured from his own screenshot of
a crisis panel bleeding off the bottom of it. A frame taken at a comfortable developer
viewport is exactly as misleading as arithmetic about `vh` units, and misleading for the same
reason: it will look fine. The card's own well is `max-height: min(52vh, 420px)`, which is
420px on a tall monitor and **209px here**, so the question *"do all four rows fit"* has
different answers on the two screens and only one of them is anybody's.

**Every frame is the WHOLE window rather than the panel that changed.** Cropped to the card,
a picture proves nothing about what it covers, and what it covers is the entire question
about the moment.

## The frames

| Frame | What it is evidence for |
| --- | --- |
| `moment-earned` | A real earning, off the city's own era state rather than the dev hatch: *"Your first age is behind you."* The card is **348x55 at (338,70), 3% of the window**, and it is clear of the Town capsule, the City Life panel, the ☰ Menu, the era chips, the Build dock and the camera controls |
| `moment-over-a-damaged-city` | The same moment over the busiest right-hand side the island ever has, with the crisis repair panel up (**320x179 at (688,200)**). The two do not overlap, and they do not read alike: the achievement is gold-ruled and the damage is red-ruled |
| `list-mixed` | The state every learner is in for most of the game: two rows earned, two still invitations, and **no count, fraction, percentage or tier anywhere on the card**. All four rows sit fully inside the 209px well |
| `list-nothing-earned` | What a new city opens to: four invitations, each reading as *"not yet"* rather than as a grade |
| `list-with-dev-hatch` | The dev instrument at the foot of the card, scrolled into frame: one button per row derived from the table (the earned one disabled), *"Forget them all"*, and the *"Dev only, not on the learner build"* eyebrow. Dark and mono on purpose, so a reviewer can tell in one look that it is not part of the game |

`measured-1024x580.txt` carries every box, its share of the window, and the verbatim
sentence on each row, regenerated by the run below.

## An honest read of them

**The moment does read as a moment, and it did not on the first try.** The first version was
the recovery note's box unchanged: the same glass fill as the Mastered chip and the City Life
panel, distinguished only by a 4px rule. On the frame it read as a **fourth HUD panel
arriving** — well-behaved, unmissable in the DOM, and completely uncelebratory. That is the
opposite of the failure everybody expects from this feature and exactly as bad, because an
achievement nobody notices earning is a row in a table. So the surface was tinted toward the
reward gold and given the list's own tick, which is enough to tell it apart at a glance and
ties it to the gold *"All built"* button the same frame already has.

**It does not get in the way.** It sits in the top-centre strip, which is the one part of
this HUD nothing else uses; it covers nothing, asks for no click, and removes itself after
eight seconds. At 3% of the window it is smaller than the repair panel it shares a screen
with.

**Two things these frames cannot answer, said rather than left to be discovered.**

- **The 3D canvas is off.** Headless Chromium has no reliable WebGL on this runner, so what
  sits behind these panels is the city's CSS backdrop (the labelled plot rectangles) and its
  full HUD, not the rendered island. Every city browser shot in this tree is taken that way.
  It is the right frame for the question being asked — the moment's neighbours are HUD
  elements, not terrain — and the wrong frame for judging the gold against the island's own
  greens, which is a look nobody can take here.
- **Whether the gold reads as *reward* or as *warning*** is a judgement about this game's
  palette that a reviewer should make. `--game-gold` is already the reward token and the
  *"All built"* button uses it, so the frame is at least internally consistent.

## Regenerating

      apps/web/src/city/achievementShots.browser.test.tsx

    cp apps/web/src/city/__screenshots__/achievements/*.png \
       apps/web/src/city/__screenshots__/achievements/*.txt \
       docs/design-refs/achievements/
    cp docs/design-refs/achievements/* output/design-refs/achievements/

**Why the shots are behind a flag, which is a measurement rather than caution.** Five
`CitySurface` mounts in one always-on browser file is the load
`cityTellsWhatItKnows.browser.test.tsx` records itself being gated for: a heavy shot suite
starves a *different* file's animation-timing assertions on a two-core runner. It happened
here on the first full run with these ungated — two assertions in
`advisorBandOverTheIsland.browser.test.tsx`, a file this branch does not touch, went red at
*"the shortfall is 238.0px"*, and both passed in isolation and on the re-run. This feature is
not on the demo's critical path and has no business making that a coin toss.

**The spatial assertions stay always-on.** One test outside the gated blocks mounts the city
once and carries every claim these frames are evidence for: where the moment sits, the four
HUD elements it does not cover, and all four rows fitting the well. So the gate costs the
pictures in CI and not the measurements.

**Why the copy into `docs/` is a command rather than the suite writing here.**
`test/testWritesStayOutOfTheTree.test.ts` keeps `npm run check` read-only against the
checkout, and every tracked-path writer it allows is one it can see a `VITE_` flag on. Adding
this suite to that list would buy a churning PNG on every run — which is the exact defect
that guard was written for, on this very directory's neighbour — so the frames are copied by
hand and the command lives here.

**The residual, inherited rather than solved** (same as `../city-says-what-it-knows/`): the
suite writes the frames and never reads them, so nothing in CI notices one of these files
being deleted. A guard that read this directory would be worse than the hole it closes,
because `invariants.yml`'s scope filter classifies `.png` inert and a frame-deleting diff
would skip the step that checked.
