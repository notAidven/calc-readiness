## §7.5 Deliberate rulings — standalone list for triage

**These refusals were examined and ruled acceptable. Do not re-file them as defects.** Each names
the node, the spelling refused, and why the refusal is correct. A–B are the report's own P3
rulings, re-verified at `3fbe5fcb`; C–E are rulings recorded in the tree rather than in the
report, and are included because a from-scratch sweep will hit them and has no other way to know.

- **A. RAT.6 refuses `three`.** A spelled-out numeral. The prompt types its own example —
  *"Type it the way this example is typed: `{-6, 1}`, and a single value may be typed bare as
  `7`"* — so the notation is stated to the learner in the question. Verified still refused.
- **B. LF.4 refuses `[2, -3]`.** Square brackets denote an interval, not a point, and the prompt
  says *"Give the solution as an ordered pair, typed like `(5, -2)`"*. The pack accepts
  `(2.0, -3.0)`, so this is a bracket ruling and not a short list. Verified still refused.
- **C. D8's EL.2, EL.4 and EL.5 are exempt from the acceptance convention.** Declared, not
  filtered: `EXEMPT_NODE_PREFIXES = ["EL."]`, `EXPECTED_EXEMPT_PACKS = 3`
  (`cfuAcceptanceConvention.test.tsx:68-69`), bounded above so the set may only shrink. The
  widening round was explicitly scoped to exclude D8 while its widgets were still being authored.
  EL.1, EL.3 and EL.6 carry a `check` and were never in the population. A short accepted list on
  EL.2/EL.4/EL.5 is next round's work, not a new finding.
- **D. A missing trailing `.0` INSIDE a multi-part answer is not a defect.** The convention
  deliberately does not enforce closure over it (`cfuAcceptanceConvention.test.tsx:26-32`):
  *"`x = -4.0, 1` is not a spelling anyone produces."* Packs still carry the `.0` form where the
  answer is a bare value — RAT.6 `3.0`, LF.4 `(2.0, -3.0)`, LF.3 `140.0`, RAT.5 `y = 3.0` — and
  that is an authoring judgement per pack. Refusing `x = -4.0, 1` is correct; refusing `140.0` is
  not, and is already fixed.
- **E. A MIXED joiner is outside the convention.** `(x + 7)/(x + 4); x = -6 and x = -4 and x = 7`
  — semicolon as the primary separator, `and` between the exclusions — is refused by RAT.2,
  RAT.3 and RAT.4, and that is by design. `withSeparator` rewrites **every** top-level separator
  to one form (`cfuAcceptanceConvention.test.tsx:184-196`), so the closure covers uniform `,`,
  uniform `;` and uniform ` and `, not combinations of them. Requiring the cross product would
  multiply every list without describing anything a learner reliably types. This ruling is mine,
  derived from the guard rather than from the report; if Stream C's solvers produce mixed joiners
  at any rate, it is worth revisiting, but it is a policy question and not an authoring gap.

## §7.6 New finding raised by this reconciliation

**RAT.2's prompt demands an order its grader no longer requires.** — **P2, domain-specific
(D5).** The prompt reads *"list every excluded value, smallest first"*, and the widened list now
accepts all six permutations, including `(x + 7)/(x + 4); x = 7, -4, -6`. This is leniency toward
a mathematically correct answer, so it is not a P0 or P1 — nothing correct is graded wrong and
nothing wrong is accepted. But the instruction is now inert, and a learner who follows it gains
nothing while one who ignores it loses nothing. Either drop *"smallest first"* from the prompt or
re-narrow the list; the first is the cheaper and is probably right, since the ordering was never
the skill being taught. Not fixed here: this stream is read-only.
